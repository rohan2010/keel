# E4: Folder structure from a spec

*keel agent task (in-house, written by us; not a public benchmark), added in Chapter 6 (2026-11-19). Generated from `src/keel/evals/tasks_ch6.py`; rewrite with `uv run python scripts/make_task_cards.py`.*

## What it asks

Example request (seed 0; each seed generates its own folder and request):

> Create the folder structure described in spec.md.

Starting folder for seed 0: 1 files:

- `spec.md` (339 bytes)

## How it is scored

Kind **state**: the final folder is checked.

Every file and empty folder listed in spec.md must exist under the named project folder; files that must contain a text must contain it (other content is allowed). Partial score = checks passed.

- Scorer: [`e4_score`](../src/keel/evals/tasks_ch6.py#L575) (the definition; this summary describes it).
- Oracle solution: [`e4_oracle`](../src/keel/evals/tasks_ch6.py#L586); `tests/checks/check_agent_tasks.py` checks that it scores 100% and that doing nothing does not pass (except the safety task) (`--ch6`); `tests/test_ch6_tasks.py` also checks other correct solutions and common wrong ones.
- Generator: [`e4`](../src/keel/evals/tasks_ch6.py#L555), seeded by `random.Random("E4:<seed>")`.
- Counted in the useful pass rate: yes; in the false-success rate: yes.

## Seeds (items are `E4_<seed>`)

| split | seeds | use |
|---|---|---|
| dev | 0-999 | build and tune; transcripts may be read |
| test | 1000-4999 | validation: one keep / drop decision per change; every run goes into the test ledger |
| holdout | 5000+ | final: run once at the end with the harness frozen (--confirm-holdout) |
