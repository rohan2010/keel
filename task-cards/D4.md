# D4: Bump the version everywhere

*keel agent task (in-house, written by us; not a public benchmark), added in Chapter 6 (2026-11-19). Generated from `src/keel/evals/tasks_ch6.py`; rewrite with `uv run python scripts/make_task_cards.py`.*

## What it asks

Example request (seed 0; each seed generates its own folder and request):

> Change the version of this project from 3.4.7 to 3.5.0 everywhere it is set.

Starting folder for seed 0: 5 files:

- `README.md` (73 bytes)
- `pyproject.toml` (81 bytes)
- `requirements.txt` (16 bytes)
- `setup.cfg` (43 bytes)
- `src/snapnote/__init__.py` (39 bytes)

## How it is scored

Kind **state**: the final folder is checked.

Every file that sets the project's version must have the new version; requirements.txt (a dependency's version, similar but not the project's) must stay; nothing else may change. Partial score = files right.

- Scorer: [`d4_score`](../src/keel/evals/tasks_ch6.py#L523) (the definition; this summary describes it).
- Oracle solution: [`d4_oracle`](../src/keel/evals/tasks_ch6.py#L541); `tests/checks/check_agent_tasks.py` checks that it scores 100% and that doing nothing does not pass (except the safety task) (`--ch6`); `tests/test_ch6_tasks.py` also checks other correct solutions and common wrong ones.
- Generator: [`d4`](../src/keel/evals/tasks_ch6.py#L502), seeded by `random.Random("D4:<seed>")`.
- Counted in the useful pass rate: yes; in the false-success rate: yes.

## Seeds (items are `D4_<seed>`)

| split | seeds | use |
|---|---|---|
| dev | 0-999 | build and tune; transcripts may be read |
| test | 1000-4999 | validation: one keep / drop decision per change; every run goes into the test ledger |
| holdout | 5000+ | final: run once at the end with the harness frozen (--confirm-holdout) |

## Run it
