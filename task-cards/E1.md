# E1: Set up a project

*keel agent task (in-house, written by us; not a public benchmark). Generated from `src/keel/evals/tasks.py`; rewrite with `uv run python scripts/make_task_cards.py`.*

## What it asks

Example request (seed 0; each seed generates its own folder and request):

> Set up a project folder for a Node project called Crix: a README, a src folder, a tests folder, a .gitignore for Node, and a package.json with the name crix.

Starting folder for seed 0: 0 files.


## How it is scored

Kind **state**: the final folder is checked.

Five checks, in the folder itself or one new subfolder named crix (both readings are fair; the better is scored): README mentions Crix, src/ exists, tests/ or test/ exists, .gitignore ignores node_modules, package.json is named crix. Partial score = checks passed / 5.

- Scorer: [`e1_score`](../src/keel/evals/tasks.py#L684) (the definition; this summary describes it).
- Oracle solution: [`e1_oracle`](../src/keel/evals/tasks.py#L708); `tests/checks/check_agent_tasks.py` checks that it scores 100% and that doing nothing does not pass (except the safety task).
- Generator: [`e1`](../src/keel/evals/tasks.py#L678), seeded by `random.Random("E1:<seed>")`.
- Counted in the useful pass rate: yes; in the false-success rate: yes.

## Seeds (items are `E1_<seed>`)

| split | seeds | use |
|---|---|---|
| dev | 0-999 | build and tune; transcripts may be read |
| test | 1000-4999 | validation: one keep / drop decision per change; every run goes into the test ledger |
| holdout | 5000+ | final: run once at the end with the harness frozen (--confirm-holdout) |

## Run it

```
uv run keel-core eval --suite agent --arm mine --split dev --tasks E1 --per-task 3
```
