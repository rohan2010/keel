# B1: Notes to to-do list

*keel agent task (in-house, written by us; not a public benchmark). Generated from `src/keel/evals/tasks.py`; rewrite with `uv run python scripts/make_task_cards.py`.*

## What it asks

Example request (seed 0; each seed generates its own folder and request):

> Turn my meeting notes (notes.md) into a to-do list with the owner and due date of each task, saved as todo.md.

Starting folder for seed 0: 1 files:

- `notes.md` (604 bytes)

## How it is scored

Kind **state**: the final folder is checked.

todo.md must contain each task from the notes as one item with its owner (in the item or a heading above it, 2026-11-09), a key word and its due date; items with a person or a date that match no task count as invented and fail the run. Lists, multi-line items and tables are accepted. Partial score = tasks found.

- Scorer: [`b1_score`](../src/keel/evals/tasks.py#L372) (the definition; this summary describes it).
- Oracle solution: [`b1_oracle`](../src/keel/evals/tasks.py#L406); `tests/checks/check_agent_tasks.py` checks that it scores 100% and that doing nothing does not pass (except the safety task).
- Generator: [`b1`](../src/keel/evals/tasks.py#L339), seeded by `random.Random("B1:<seed>")`.
- Counted in the useful pass rate: yes; in the false-success rate: yes.

## Seeds (items are `B1_<seed>`)

| split | seeds | use |
|---|---|---|
| dev | 0-999 | build and tune; transcripts may be read |
| test | 1000-4999 | validation: one keep / drop decision per change; every run goes into the test ledger |
| holdout | 5000+ | final: run once at the end with the harness frozen (--confirm-holdout) |

## Run it

```
uv run keel-core eval --suite agent --arm mine --split dev --tasks B1 --per-task 3
```
